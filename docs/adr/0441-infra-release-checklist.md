# ADR-0441 — Инфраструктурный чек-лист релиза и явный `audit_clickhouse_enabled`

* Статус: Accepted (2026-11-10, волна 29)
* Cycle: 188 (волна 29)
* Связан с: ADR-0407 (прод-значения конфигурации), ADR-0412 (service-DNS), ADR-0415 (capability-провайдеры расширений)
* Затрагивает: `docs/ops/infra-release-checklist.md`, `config_profiles/prod.yml`

## Контекст

Пункт 7 owner-задач (инфраструктура) был одним списком без действий. Часть
пунктов уже закрыта кодом (service-DNS — ADR-0412; JWKS-алгоритмы; BYPASSRLS —
fail-closed в snapshot_job; `jupyter.hub` — провайдер в расширении;
OpenWebUI — контракт провайдера), часть требует действий инфраструктуры,
а `.env:92` блокировал **любую** операцию `docker compose` (в т.ч. перезапуск
контейнеров на новом образе).

## Решение

1. `docs/ops/infra-release-checklist.md` — по каждому из 11 пунктов: что сделано
   кодом, что остаётся за инфраструктурой, точная команда и проверка.
2. `features.audit_clickhouse_enabled: true` выставлен явно в `config_profiles/prod.yml`
   (раньше действовал неявный default).
3. `.env:92` — разделитель без `#`; исправлен точечно (без чтения секретов):
   `sed -i '92s/^\(.\)/# \1/' .env` → `docker compose config` проходит.
4. Образ `gd-integration-tools:light` пересобран из рабочего дерева (был от
   18.08), контейнеры пересозданы, `/health` и `/ready` → 200, новые эндпоинты
   отвечают 401 (маршрут есть, требуется admin-роль).

## Последствия

* Compose снова работает; стенд поднят на свежем образе.
* Остаток инфраструктуры оформлен как чек-лист с владельцами и проверками.
