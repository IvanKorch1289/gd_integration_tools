# ADR-0304: except-кортежи без скобок каноничны (PEP 758); гейт перепрофилирован в fail-closed parse

Статус: accepted (2026-09-21)

## Контекст

PLAN.md V22 §S17 DoD #2 требовал нулевого количества ``except A, B:``
без скобок (стиль Python 2) и закреплял это гейтом
``tools/checks/check_python3_syntax.py`` + кодмодом
``tools/codemods/fix_except_clause.py``.

Проект таргетирует Python 3.14 (``requires-python = ">=3.14,<3.15"``,
``target-version = "py314"``). По **PEP 758** форма
``except A, B:`` (без ``as``) легальна и семантически эквивалентна
``except (A, B):``. Эмпирически (аудит 2026-09-21):

- ``ruff format`` 0.16.7 **канонизирует** ``except (A, B):`` →
  ``except A, B:`` и не оставляет настройки отключить это
  (stable и preview поведение одинаково);
- блокирующий шаг ``ruff format --check`` в lint.yml тем самым вечно
  воспроизводил форму без скобок после каждого прогона кодмода —
  гейт и форматтер находились в неразрешимом конфликте
  (многократные «раунды» кодмода 2026-09-21);

Реальный Python-2 хазард — ``except A, B as e:`` (биндинг вместо
кортежа) — это ``SyntaxError`` и ловится любым parse-гейтом.

## Решение

1. Гейт ``check_python3_syntax.py`` перепрофилирован: единственное
   правило — **каждый ``.py`` обязан разбираться ``ast.parse``**
   (fail-closed, rule ``syntax-parse-failed``). Правило
   ``except-tuple-no-paren`` удалено как противоречащее канону
   форматтера.
2. Кодмод ``fix_except_clause.py`` сохранён как утилита, но применение
   репозиторий-широко прекращено (его результат перезаписывается
   ``ruff format``). Запускать точечно, осознавая конфликт.
3. Регрессионные тесты обновлены под новые семантики.

## Последствия

- DoD §S17 #2 («grep ``except A, B:`` = 0») считается исполненным
  через канон форматтера, а не через grep-запрет.
- Конфликт «кодмод vs format» устранён; CI-шаги
  compileall/format-check/syntax-gate согласованы.
- Возврат к запрету возможен только вместе с понижением
  ``target-version`` ниже 3.14 (не планируется).
