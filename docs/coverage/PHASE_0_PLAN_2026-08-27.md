## 2. Phase 0 target: per-layer split (OOM mitigation)

### 2.1 Why per-layer split?

Current `make coverage-gate` runs:
```bash
pytest tests --cov=src/backend --cov-report=xml --cov-report=term --maxfail=20 -n auto
```

**Issue**: `--cov=src/backend` covers ALL source в одном process. pytest-xdist
workers (`-n auto`) каждый hold full coverage data → memory amplification
(peak ~4GB per worker на full unit suite).

### 2.2 Per-layer split pattern

```makefile
# New Makefile target (Sprint 36 W1)
coverage-per-layer: ## Sprint 36 W1: per-layer coverage split (Phase 0)
	@$(INFO) "Sprint 36 W1 Coverage Phase 0: per-layer split..."
	@rm -f .coverage .coverage.* coverage.xml .coverage_*.xml
	@for layer in core services entrypoints infrastructure workflows dsl; do \
		echo "=== Running tests for layer: $$layer ==="; \
		$(UV_RUN) pytest tests --cov=src/backend/$$layer \
			--cov-append --cov-report=xml:.coverage_$$layer.xml \
			--no-cov-report=term -n auto --maxfail=5 \
			--ignore=tests/integration -q || true; \
	done
	@$(UV_RUN) python -m coverage combine
	@$(UV_RUN) python tools/coverage/breakdown_by_layer.py coverage.xml \
		| tee .baselines/coverage_per_layer_$(date +%F).log
```

### 2.3 Why `--ignore=tests/integration`?

Integration tests требуют Docker (Redis, ClickHouse, postgres) — not
available в dev_light environment. Per-layer split фокусируется на unit tests
для memory profiling (Phase 0 goal = verify OOM mitigation, NOT ratchet).

- `services` ≥ 60% (many legacy facade paths, harder)

(considers test-writing capacity, S33 inventory >3500 tests). Faster rates
(>10pp) риск OOM в CI + reviewer fatigue.
