## 4. Sprint 55 implementation details

### 4.1 W1: JWT path rotation integration

**Problem**: S54 W2 wired demo path to rotation store. JWT path (when `mobile_jwt_enabled=True`) was unchanged — same JWT could be used for refresh multiple times within TTL.

**Solution**: Minimal change to JWT path (~20 LOC):
1. After JWT verify (ctx obtained) + device_id check
2. `store.issue_if_new(user_id, device_id, ctx.jti, ttl)` — atomic first-use check
3. If False (reuse detected) → 401 with "JWT already used" detail
4. If True → return new tokens

**Design insight**: JWT jti is FOREIGN (from external auth provider), not generated by us. So existing `is_valid + revoke + issue` rotation semantic doesn't fit. Added new `issue_if_new()` method that atomically checks + adds — single op semantics for first-use detection.

**Tests added**: 5 in `test_refresh_jwt_rotation.py`
- `test_jwt_first_use_succeeds` — legitimate refresh with new JWT → 200
- `test_jwt_reuse_detected_returns_401` — replay same JWT → 401
- `test_different_jwt_jti_independent` — different JWTs work in parallel
- `test_jwt_per_user_isolation` — same jti for different users = OK
- `test_jwt_invalid_signature_skips_rotation_check` — fail-CLOSED (auth before rotation)

**Test pattern**: `@asynccontextmanager` keeps `patch.dict(sys.modules, ...)` active throughout async request lifecycle. Critical for mocking `feature_flags.mobile_jwt_enabled=True` at request time.

**Bug fixed during implementation**: Cross-test state contamination in existing JWT integration tests (S49 W3 hardcoded `VALID_JWT_CLAIMS["jti"]="jti-refresh-test"` → second test fails with reuse detection). Added `reset_mobile_state()` to JWT test helper.

### 4.2 W2: Redis-backed rotation store

**Problem**: `InMemoryRefreshTokenStore` works for single-pod but is state-local — multi-pod deployment loses rotation tracking (each pod has its own set, so rotated tokens look "fresh" on other pods).

**Solution**: New `RedisRefreshTokenStore` class (~165 LOC) implementing same Protocol:
- Key format: `gd:mobile:refresh:<user_id>:<device_id>:<jti>`
- Value: timestamp string (existence = valid)
- TTL: per-issuance via `cache_set(expire=ttl)`
- `issue_if_new` uses atomic `SET NX EX` via `execute("cache", lambda conn: conn.set(key, "1", nx=True, ex=ttl))`

**Atomicity**: Redis `SET NX EX` is single atomic op — no race condition between concurrent refresh requests across pods. Same property as in-memory `set.add()` under GIL.

**Fail-CLOSED**: `is_valid` and `issue_if_new` return False on Redis errors (conservative — don't accept potentially-stolen tokens when store is unavailable).

**Factory selection** (in `refresh_token_store.py`):
```python
def get_refresh_token_store():
    if os.environ.get("REDIS_ENABLED", "").lower() == "true":
        return RedisRefreshTokenStore()
    return InMemoryRefreshTokenStore()  # default
```

**Tests added**: 14 in `test_refresh_token_store_redis.py`
- Key format validation
- `is_valid` True/False cases + Redis-error fail-CLOSED
- `issue` TTL propagation + invalid args rejection
- `issue_if_new` True/False cases + NX atomicity verification + fail-CLOSED
- `revoke` deletion + Redis-unavailable graceful
- Custom key prefix
- Full rotation cycle end-to-end

**Mock pattern**: `_capture_execute` lambda captures the inner `conn.set(...)` lambda so test can invoke it manually with a mock conn. This verifies the actual redis-py call signature (`nx=True, ex=ttl`) rather than just trusting `execute` was called.

## 8. Lessons captured

### 8.1 What worked

1. **`@asynccontextmanager` pattern**: keeps patches active throughout async request lifecycle. Critical for mocking at request time vs import time.
2. **Atomic SET NX EX**: single Redis op for first-use detection — same atomicity guarantee as in-memory `set.add()` under GIL.
3. **Protocol-driven factory**: `get_refresh_token_store()` selects impl based on `REDIS_ENABLED` env. Same Protocol interface, no caller changes needed.
4. **Bug discovery via cross-test state**: existing JWT tests had hardcoded jti → second test failed after integration. Added `reset_mobile_state()` to test helper. Same pattern as S54 W2.
5. **`_capture_execute` lambda pattern**: verifies actual redis-py call signature rather than just "execute was called".

### 8.2 What didn't work

1. **First attempt: `with patch.dict(...)` outside `async with`**: patches exited before request processing → feature_flags wasn't mocked → JWT path didn't run. Took 1 test failure to identify.
2. **Initial test for SET NX**: tried to invoke lambda manually without capturing it. Fixed with `_capture_execute` side_effect pattern.

### 8.3 What to do differently in S56

1. **Always use `@asynccontextmanager` for AsyncClient + patch combinations** — pattern established, reuse it.
2. **Pre-verify factory env handling**: check if existing tests use env vars that would be overridden by new factory selection.
