**Key insight**: `vector_store.py` remains a module file (NOT a package),
so the import path `from src.backend.infrastructure.clients.storage.vector_store import X`
is unchanged. The module body is now just re-exports + factory.

### 1.4 Why this refactor matters (production impact)

1. **Single responsibility per file**: each backend is now a focused module.
   Future ChromaVectorStore deprecation (due to CVE) can be done by
   deleting `chroma.py` + removing 1 line from `vector_store.py` — no
   risk of accidentally breaking Qdrant or FAISS.

2. **Better testability**: each backend can be tested in isolation
   (currently all 8 tests live in one file). Future work: split
   `test_vector_store.py` into `test_qdrant.py`, `test_chroma.py`,
   `test_faiss.py` for faster feedback.

3. **Better git history**: changes to one backend now have a focused
   diff (only `qdrant.py` or `chroma.py` changes, not the whole file).
   Code review becomes easier.

4. **Better IDE support**: jumping to QdrantVectorStore definition
   now goes to a 249-LOC file, not a 599-LOC one with 3 classes.

### 1.5 What was NOT done (out of scope)

- **InMemoryBackend as separate module**: the FAISS in-memory backend
  serves the same purpose (in-memory, no external deps). Adding a
  4th InMemoryBackend would be redundant.
- **PgVectorBackend**: P2 backlog. Not extracted because no production
  code uses it (would be premature).
- **Splitting BaseVectorStore ABC**: already in `core/interfaces/vector_store.py`
  (correctly separated from implementations).
