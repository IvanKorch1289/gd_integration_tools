# ADR-0352.1: Migration Guide — Core-facade → Services-facade

> **Status**: ACTIVE (Cycle 166, ADR-0352 Stage 3)
> **Audience**: extension developers + consumers of `core.cache.facade`
> **Target**: Cycle 167 (Stage 4) — `MemoryCacheFacade`, `FallbackCacheFacade`,
> `RedisCacheFacade` будут удалены.

## TL;DR

```python
# ❌ OLD (deprecated since cycle 166, will be removed cycle 167)
from src.backend.core.cache.facade import (
    MemoryCacheFacade, FallbackCacheFacade, RedisCacheFacade,
)

# ✅ NEW (production canonical — Cycle 165)
from src.backend.services.cache import UnifiedCacheFacade

# ✅ NEW (dev/test path — Core ABC impl через DI)
from src.backend.core.di.providers.cache import get_cache_facade
```

## Что изменилось

### Cycle 165 (Stage 2): MERGE
- `services.cache.UnifiedCacheFacade` теперь `extends` `core.cache.UnifiedCacheFacade` ABC.
- Оба класса IS-A core ABC → type checks работают в обоих направлениях.
- ABC abstract methods (`get`, `set`, `delete`, `delete_by_tag`, `exists`, `healthcheck`)
  реализованы в services facade.

### Cycle 166 (Stage 3): DEPRECATE
- `core.cache.facade.{MemoryCacheFacade, FallbackCacheFacade, RedisCacheFacade}` помечены
  `DeprecationWarning`.
- ABC (`UnifiedCacheFacade`) остаётся canonical interface.
- При instantiation deprecated классов — warning в stderr.

### Cycle 167 (Stage 4): REMOVE — TBD
- Все deprecated concrete impls будут удалены.
- `core.cache.UnifiedCacheFacade` ABC остаётся.

## Migration patterns

### Pattern 1: DI-registered facade (production)

```python
# BEFORE (core + DI):
from src.backend.core.di.providers.cache import get_cache_facade
facade = get_cache_facade(enable_fallback=True)
await facade.set("key", b"value")

# AFTER (services):
from src.backend.services.cache import get_unified_cache_facade
facade = get_unified_cache_facade(plugin="my_plugin")
await facade.set_ns("key", b"value", namespace="my_ns")
# OR (ABC-style):
await facade.set("key", b"value", ttl_seconds=300)
```

### Pattern 2: Direct instantiation

```python
# BEFORE (deprecated):
from src.backend.core.cache.facade import MemoryCacheFacade
facade = MemoryCacheFacade(maxsize=1000)

# AFTER (production):
from src.backend.services.cache.facade import UnifiedCacheFacade
from src.backend.infrastructure.cache.backends.memory import MemoryBackend
primary = MemoryBackend(maxsize=1000)
facade = UnifiedCacheFacade(primary=primary)  # без fallback'а
# OR с 3-tier:
facade = UnifiedCacheFacade(
    primary=primary,
    memory_fallback=MemoryBackend(maxsize=500),
    disk_fallback=DiskCacheBackend(base_path="/var/cache"),
)
```

### Pattern 3: Redis production

```python
# BEFORE (deprecated):
from src.backend.core.cache.facade import RedisCacheFacade
from src.backend.infrastructure.cache.factory import create_cache_backend
from src.backend.core.config.services.cache import cache_settings
backend = create_cache_backend(cache_settings)
facade = RedisCacheFacade(backend=backend)

# AFTER (canonical):
from src.backend.services.cache.facade import UnifiedCacheFacade
from src.backend.infrastructure.cache.factory import create_cache_backend
from src.backend.core.config.services.cache import cache_settings
primary = create_cache_backend(cache_settings)
facade = UnifiedCacheFacade(primary=primary)
```

## API mapping table

| Core (deprecated) | Services (canonical) | Notes |
|---|---|---|
| `get(key)` | `get(key)` или `get_ns(key, namespace)` | ABC parity |
| `set(key, value, ttl_seconds, tags)` | `set(key, value, ttl_seconds, tags)` или `set_ns(...)` | ABC parity |
| `delete(*keys)` | `delete(*keys)` или `delete_ns(*keys, namespace)` | ABC parity |
| `delete_by_tag(tag)` | `delete_by_tag(tag)` или `delete_by_tag_ns(tag, namespace)` | ABC parity |
| `exists(key)` | `exists(key)` или `exists_ns(key, namespace)` | ABC parity |
| `healthcheck()` | `healthcheck()` или `healthcheck_ns()` | ABC parity |
| (no namespace param) | `namespace='default'` (default) | NEW |
| (no CacheResult) | `CacheResult(value, hit, backend)` | NEW observability |
| (no capability check) | `_check(plugin, capability, namespace)` | NEW |
| `FallbackCacheFacade(primary, fallback)` | `UnifiedCacheFacade(primary=..., memory_fallback=..., disk_fallback=...)` | Built-in 3-tier |
| `RedisCacheFacade(backend)` | `UnifiedCacheFacade(primary=backend)` | Single-tier достаточен |

## Type checks

```python
from src.backend.core.cache.facade import UnifiedCacheFacade as CoreABC
from src.backend.services.cache.facade import UnifiedCacheFacade as ServicesFacade

# Services facade IS-A Core ABC.
assert issubclass(ServicesFacade, CoreABC)  # ✅

# Type hints with Core ABC accept Services facade.
def my_helper(facade: CoreABC) -> None: ...

my_helper(ServicesFacade(primary=...))  # ✅ OK
```

## Capability check (production)

Services facade имеет встроенный capability check:

```python
from src.backend.core.security.capabilities import CapabilityGate

gate = CapabilityGate(...)
facade = UnifiedCacheFacade(
    primary=...,
    capability_check=gate.check,  # callback signature
    plugin="my_plugin",
)
# При set/get/delete автоматически вызывается gate.check("my_plugin", "cache.read", namespace).
```

Core facade не имеет capability check — extension получает его только через services facade.

## Что НЕ изменилось

- `UnifiedCacheFacade` ABC остаётся canonical interface (Cycle 165 → services extends it).
- `CacheError`, `CacheInvalidationPolicy` остаются в core (используются ABC + impls).
- `core.cache.rag.ThreeTierRagCache` не затронут (отдельный path для RAG cache).
