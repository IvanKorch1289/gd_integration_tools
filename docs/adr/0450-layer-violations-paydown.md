# ADR-0450 — План погашения межслойных нарушений (40 → 0) с рэтчетом

* Статус: Accepted (2026-11-17, волна 33)
* Cycle: 189 (волна 33)
* Связан с: ADR-0348 (baseline межслойных нарушений), ADR-0284 (матрица слоёв), ADR-0430 (caller-aware capability)
* Затрагивает: `tools/check_layers.py`, `tools/check_layers_{allowlist,contract}.txt`, `src/backend/{core,services,entrypoints,infrastructure,dsl}/**`

## Контекст

`check_layers.py --strict` показывал 41 нарушение матрицы слоёв; первым
шагом волны SSRF-guard webhook-планировщика переведён из DSL в core
(`core.net.url_guard`), и baseline сокращён **41 → 40**.

| Группа | Нарушений | Суть |
|---|---|---|
| `core/ → services/` | 6 | ядро импортирует сервисы (AI-gateway, guardrails, authorization) |
| `dsl/ → extensions/` | 6 | DSL-регистрация тянет бизнес-расширения |
| `entrypoints/ → extensions/` | 18 | HTTP-эндпоинты импортируют схемы/сервисы расширений напрямую |
| `services/ → extensions/` | 3 | сервисы знают о расширениях |
| `infrastructure/ + workflow/ → dsl/` | 4 | инфраструктура/раннер знают о DSL |
| `services/ → dsl/` | 3 | сервисы знают о DSL |
| **Итого** | **40** | baseline: долг 37 + контракты 3 (ADR-0348, вариант C) |

Часть нарушений — **композиционный** код (регистрация действий, сборка
роутов), где прямой импорт расширений — сознательное исключение
(ADR-0284: extensions регистрируются в composition root). Остальные —
настоящие инверсии: бизнес-логика расширений протекает в core/entrypoints.

## Решение

1. **Рэтчет вместо разового большого рефакторинга.** Baseline слоёв
   фиксирует текущие 40 нарушений (долг 37 + контракты 3); гейт блокирует
   **новые** и падает на «стейл»-записях (нарушение исправлено, запись
   забыта). Каждая волна сокращает baseline (ADR-0348).
2. **Инверсия по доменам** — целевая архитектура:
   * `core/ → services/`: общие контракты (Protocol) переносятся в `core/`,
     реализация остаётся в `services/`, регистрация — в composition root;
   * `entrypoints/ → extensions/`: эндпоинты обращаются к действиям через
     `ActionHandlerRegistry` (уже есть `dsl/commands/action_registry.py`),
     а не к сервисам расширений напрямую;
   * `services/ → extensions/` и `→ dsl/`: плагин-регистрация переносится в
     composition root (`plugins/composition/setup*`), сервисы работают через
     core-контракты;
   * `infrastructure/ + workflow/ → dsl/`: `Exchange`/регистры дублируются в
     `core/` как Protocol.
3. **Безопасность каждого шага:** атомарный коммит на одну группу, после
   каждого — `check_layers --strict`, целевые тесты и полная регрессия.
4. **Контракт ≠ долг:** осознанные зависимости `services/ → dsl` живут в
   `tools/check_layers_contract.txt`, реальный долг — в
   `tools/check_layers_allowlist.txt`; пересечение двух файлов запрещено
   (тест `test_check_layers_contract_baseline.py`).

## Последствия

* Baseline межслойных нарушений уменьшается от 40 к 0 шаг за шагом; CI
  блокирует рост уже сейчас.
* Начинать следует с `services/ → dsl/` (3 нарушения, локальные правки) и
  `infrastructure/ + workflow/ → dsl/` (4) — они не затрагивают публичные API.
* Группы `entrypoints/ → extensions/` (18) — самые крупные: перевод
  эндпоинтов на action-реестр (ADR-0284 V22), отдельными волнами.
* Устранение нарушения обязано удалять запись из baseline: иначе гейт
  падает как на «стейл», а не на новых нарушениях.

## Уточнение волны 34 (2026-11-18) — план исполнен, долг обнулён

Документ фиксирует план на момент принятия (волна 33). Фактический итог:

| Группа (из «Контекста») | План | Факт (волна 34) | Закрывающий ADR |
|---|---|---|---|
| `core/ → services/` | 6 | 0 — реализация AI перенесена в `core/ai/gateway/*`, в `services/ai/*` остались re-export шимы | ADR-0457 |
| `dsl/ → extensions/` | 6 | 0 | ADR-0457 (core-реестр ресурсов расширений) |
| `entrypoints/ → extensions/` | 18 | 0 | ADR-0457 |
| `services/ → extensions/` | 3 | 0 | ADR-0457 |
| `infrastructure/ + workflow/ → dsl/` | 4 | 0 — `Exchange` перенесён в `core/engine/exchange.py`, зависимости — инъекцией | ADR-0457 |
| `services/ → dsl/` | 3 | 3 — **осознанные контракты**, не долг | ADR-0348 (вариант C) |

Итог по гейту: `tools/check_layers.py` → **0 новых нарушений, долг 0,
контрактов 3** (`tools/check_layers_contract.txt`); в строгом режиме
(`--strict`) гейт возвращает 3 — это осознанные `services → dsl` контракты,
их устранение требует переноса `BaseProcessor` в core (решение по матрице
слоёв), а не правки кода. Проверка честности инверсии: число путей OpenAPI
не изменилось (447 до и после).

**Рекомендация владельцу:** долг 0 ≠ долг закрыт окончательно — 3 записи
контракта следует либо принять как постоянные (зафиксировать в ADR-0284),
 либо свести к 0 переносом `BaseProcessor` в `core/`.
