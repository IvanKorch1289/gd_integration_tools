### 2.3 Backward compatibility (zero breakage)

### 2.4 Why this refactor matters

1. **Single responsibility per file**: types / auto-generation / dispatch
   helpers / facade — 4 different concerns, now 4 different files.
2. **Easier testing**: each module can be tested in isolation.
3. **Better IDE support**: jumping to a class definition now goes to a
   focused file, not a 825-LOC monolith.
4. **Future strawberry.federation split** (S168 W11 P2-4) is now
   trivial — types.py is the canonical source, and the per-domain
   resolvers can be assembled from the 4 file modules.

### 2.5 What was NOT done (out of scope)

- **Strawberry federation split** (separate WIP per the file's
  docstring migration plan). The current architecture uses
  auto-generation from `ActionMetadata`, which is good enough for
  the current 131 actions.
- **Ponytail principle**: full split into order_query.py, order_mutation.py,
  etc. would require per-domain resolver decomposition — P2 backlog.
