## ⏸️ 6/16 файлов — требуют multi-session refactor

Эти файлы используют service symbols, которые **возвращают service objects** (не данные). Для их миграции нужен:

1. Новый backend endpoint (thin wrapper)
2. Новый client method
3. Рефактор UI для работы с DTO вместо service object

| # | Файл | Service symbol | Issue |
|---|---|---|---|
| 1 | `32_DSL_Конструктор.py` | `get_dsl_builder_service()` | Возвращает `DSLBuilderService` object с методами `list_routes()`, `register()`, `update()` — нужен backend API + UI rework |
| 2 | `63_Вики.py` | `get_whoosh_index()` | Возвращает `_WhooshIndexFactory` (DI factory) — нужен HTTP endpoint для wiki search |
| 3 | `96_Монитор_зависших_сообщений.py` | `get_default_stuck_monitor()` | Возвращает `StuckMonitor` object с методами `start()`, `stop()`, `get_metrics()` — нужен service proxy |
| 4 | `schema/import_tab.py` | `get_import_service()` | Возвращает `ImportService` object — нужен HTTP endpoint для DSL import |
| 5 | `_editor/properties.py` | `load_pipeline_from_yaml()` | **Pure utility function** (parse YAML → Pipeline object) — нет HTTP equivalent, нужна замена на DTO-based pipeline representation |
| 6 | `_editor/visual/tab_canvas.py` | `load_pipeline_from_yaml()` | (same as #5) |
| 7 | `_editor/yaml_sync.py` | `load_pipeline_from_yaml()` + `Pipeline` class | (same as #5) |

**Три файла `_editor/*` (properties, tab_canvas, yaml_sync) используют одну pure utility function**. `load_pipeline_from_yaml` парсит YAML и создаёт in-memory `Pipeline` объект. Это не service call, а data transformation. Per layer rules frontend может иметь свою копию — но это дублирование кода. Рекомендация: оставить facade import для pure utilities, мигрировать только service calls.
