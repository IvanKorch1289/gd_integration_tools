## 3. Что закрыто кодом (волна 33)

### 3.1. Реальный enforcement `audit.write` (ADR-0454)

* `AuditProcessor.process()` вызывает `auth_check()` **до** обращения к
  sink'у: без декларации capability → `failed` + `stopped`, запись не
  выполняется.
* Scope запроса — `audit:<action>` (точки → двоеточия: matcher `audit.write` —
  dot-glob); декларации 5 роутов — `audit:*`.
* Тест переведён на **реальный** гейт (`REAL_CAPABILITY_GATE = True`): без
  подмены `auth_check` из `tests/unit/dsl/conftest.py` проверка была бы
  вакуумной — это и нашёл независимый агент.

### 3.2. Групповой coverage действительно работает (ADR-0453)

Исправлено 6 дефектов, из-за которых CI-джоб падал: имя части покрытия
(`.coverage.<group>`), порог `fail_under` на группе, пустые группы (exit 5),
`tests/chaos` (нет `pytest-toxiproxy`), `tests/integration` (живые сервисы),
stale `.coverage` в корне.

### 3.3. Инфраструктурные артефакты применимы (ADR-0455)

* генератор JWKS: отклоняет корень репозитория, переживает повторный
  прогон (ротация ключа), покрыт 4 тестами;
* SQL-роль снапшота: применена на временном PostgreSQL 16.15 — роль
  `snapshot_service` (NOLOGIN BYPASSRLS) + `snapshot_service_login`,
  `GRANT SELECT` на 5 таблиц снимка, идемпотентно, `SET ROLE` читает и не
  может писать;
* чек-лист: реальные env-имена, https-требование к JWKS, команды и проверки
  для всех 11 пунктов.

### 3.4. CVE-гейт: 23 уязвимости закрыты

`make cve-gate` не доходил до отчёта: `uv export` отдавал по версии на
платформу (`click 8.3.3` для darwin + `click 8.5.0` для linux), `pip-audit`
падал на конфликте установки. После дедупа по имени пакета гейт показал
реальную картину — 23 CVE в 6 пакетах — и они закрыты обновлениями lock
(для `filelock` потребовался `override-dependencies`: `litellm` пинит
`<4.0`; приём уже применялся в проекте для других CVE).

### 3.5. Прочие исправления

* fail-closed для UNION/CTE (ADR-0448): сущности видны в ветвях/определениях —
  раньше запрос с пустым tenant уходил без предиката;
* `net.outbound.open.er-api.com` → `net.outbound.erapi`: имя с дефисом не
  проходило грамматику `CapabilityRef` → capability нельзя было объявить
  ни в `route.toml`, ни в `plugin.toml`;
* каталог `docs/reference/capabilities.md` пересобран (гейт свежести падал
  после миграции ADR-0451);
* baseline слоёв: долг и контракты разделены (было пересечение 3 записей),
  стейл-запись `webhook_scheduler` удалена → гейт снова exit 0;
* `LiteLLMModel`: pydantic-ai 1.x требует абстрактный `Model.system` (адаптер
  нельзя было создать), адаптер терял сообщения в формате `dict`;
* OCR-тесты пропускаются без optional-extra `pytesseract` (в CI-джобе без
  extras они падали);
* `deepeval 2.5.5 → 4.3.4`: `make setup` (`uv sync --all-extras`) ронял
  коллекцию AI-тестов (`No module named langchain.schema`).

## 5. Дорожная карта развития

### Горизонт 1 — «не дать регрессий» (1–2 недели)

1. Engine-wide enforcement capability + CI-гейт на декларации процессоров.
2. Перемер coverage на CI-раннере (скрипт починен) → обновление baseline.
3. Pre-existing падения сьютов вне CI-скоупа (`property`, `security` →
   `ssl.CERT_NONE` в graylog, `smoke`, `workflow`).
4. Ревью allowlist CVE (дата ревью, severity, обоснование).

### Горизонт 2 — «закрыть продуктовые оговорки» (2–6 недель)

1. Инфраструктурные 6 действий (владелец платформы) + сверка в проде.
2. Инверсия межслойных зависимостей: `services/ → dsl/` (3), `infrastructure/
   + workflow/ → dsl/` (4), затем `entrypoints/ → extensions/` (18).
3. Миграция внутренних потоков на явный `system_tenant_context()`.

### Горизонт 3 — «развитие» (1–3 месяца)

1. Capability-каталог как единый источник для портала и документации.
2. Cookbook по workflow-Temporal (после 2 недель трафика).
3. Персистентность checkpoint'ов workflow.
