## 🟡 WARNINGS (3)

### W-1. SOAP DSL-routed операции всё ещё теряют principal
**Файл**: `src/backend/entrypoints/soap/soap_handler.py:194-204`. Цикл 5 закрыл только ветку
`if action_handler_registry.is_registered(operation)` (L195-198). Для DSL-routed операций
(«Стратегия 2» через `get_dsl_service().dispatch(route_id, payload)`) проброс `principal`/
`permissions` НЕ выполнен — `cmd.meta.principal` остаётся пустым для Tier-1/2 DSL-routes
через SOAP.

**Fix**: передать `soap_auth = getattr(request.state, "auth", None)` через call в DSL;
добавить тест `test_dsl_principal_propagation.py`.

### W-2. GraphQL `info.context["auth"] is None` — fail-closed не enforced
**Файл**: `src/backend/entrypoints/graphql/schema.py:60-63`. `_graphql_context_getter`
возвращает `{"auth": None}` с комментарием «fail-closed». Но fail-closed работает только
если consumer (`_principal_from_info`, resolvers) корректно обрабатывает `None`. Из
CURRENT_STATE: «resolvers получали anonymous principal» → проблема была в consumer'е,
а не в context wiring. Wiring — необходимая, но НЕ достаточная мера.

**Проверить в WAVE 3**: grep `info.context.get("auth")` / `principal_from_info` — что
возвращается при `auth=None`. Добавить regression-тест «anonymous context → permission
check raises/forbidden».

**✅ Cycle 27 verification (2026-08-27)**: fail-closed contract VERIFIED
существующими 19 тестами в `test_schema_auth_propagation.py`:
- `test_principal_from_info_without_auth` → returns `""` ✓
- `test_principal_from_info_none` → returns `""` ✓
- `test_permissions_from_info_no_auth` → returns `()` ✓
- `test_permissions_from_info_none` → returns `()` ✓
- `test_anonymous_fails_closed_on_protected_route` → status="failed", principal="anonymous" ✓
- `test_resolver_without_auth_in_context` → fail-closed ✓

W-2 closed без дополнительного кода — fail-closed был реализован в cycle 4
context_getter fix + существующие unit tests.
