### 1.3 Why pre-audits missed the syntax error

The `extensions.py` file (commit 3853ef55) was added in round 2 as the
"untracked facade" fix. The commit's body referenced "1 NEW + grep" but the
file was committed by the parallel process. Whoever added the `extensions.py`
comment-broken import in `admin_parallelism.py:37` was the SAME parallel
process during the Sprint D.3-D.4 refactor (1bb76b0a).

The broken import:
```python
from src.backend.core.api.extensions import # NOTE: facade doesn't
    re-export ParallelismAnalyzer; using full path import ParallelismAnalyzer
```

This is `from ... import # COMMENT` — Python parser REJECTS this as SyntaxError.
Bandit's behavior on SyntaxError: SKIP the file. So all findings inside
admin_parallelism.py (1 ruff + 1+ bandit) were silently dropped from
subsequent audits.

**The lesson**: Always parse-check newly added files in CI before relying on
audit numbers. Add a "fail ruff/py_compile on SyntaxError" gate to catch this
in future.
