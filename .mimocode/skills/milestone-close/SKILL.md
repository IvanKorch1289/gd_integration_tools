# Закрытие milestone

Закрой milestone: $ARGUMENTS

## 1. Восстановить контракт

1. Прочитай актуальные `AGENTS.md`, релевантные разделы `CLAUDE.md` и `PLAN.md`.
2. Найди исходные критерии milestone в плане, checkpoint/memory и пользовательских сообщениях.
3. Составь таблицу: критерий → доказательство → статус `DONE | GAP | BLOCKED`.
4. Не расширяй scope предположениями. Новую крупную работу вынеси в следующий milestone.

## 2. Зафиксировать baseline

1. Проверь `git status` и не трогай чужие изменения.
2. Выбери минимальные targeted checks для затронутой области.
3. Запиши существующие падения отдельно; регрессионный бюджет — ноль.

## 3. Закрыть GAP

1. Следуй Ponytail/YAGNI и архитектурным границам проекта.
2. Делай одну логическую правку за шаг.
3. После каждого шага запускай минимальную targeted-проверку.
4. При новом падении остановись, установи причину и исправь до продолжения.

## 4. Review gate

Проведи ревью изменённых файлов по трём перспективам:

- **Security**: fail-open, trust boundaries, secrets/PII, небезопасная десериализация и выполнение.
- **Architecture**: границы слоёв, фасады/DI, domain-agnostic core, DSL-покрытие, обратная совместимость.
- **Operations**: async/resource lifecycle, retries/timeouts, observability, fallback, deployment/runtime impact.

Для каждого замечания укажи `file:line`, severity и конкретную правку. Исправь блокирующие и существенные замечания, затем повтори review затронутого diff.

## 5. Финальная проверка

1. Запусти targeted tests.
2. Запусти минимально достаточные `make lint`, `make type-check` и дополнительные checks для DSL/DI/contracts/docs.
3. Для структурных изменений выполни `graphify update .`.
4. Сравни результаты с baseline и явно подтверди нулевую регрессию либо перечисли блокеры.

## 6. Ретроспектива и stopping condition

Верни компактно:

- критерии milestone и доказательства закрытия;
- изменённые файлы;
- результаты security/architecture/ops review;
- выполненные проверки и отличие от baseline;
- оставшийся техдолг, относящийся только к этому milestone;
- статус `CLOSED` только если все критерии `DONE`, review не содержит блокеров и регрессий нет.

Commit выполняй только по явному указанию пользователя. Перед commit покажи точный состав, используй Conventional prefix и не делай push без отдельного разрешения.
