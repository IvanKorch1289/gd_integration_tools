# ADR-0289: pypdf 6.14.2 → 6.16.1 (CVE patch + minor)

## Status
Accepted (2026-09-01)

## Context
`pip-audit` (S52 M3-#1) reveals:

| CVE | Title | Severity |
|---|---|---|
| PYSEC-2026-3655 | pypdf XFA parsing | High |
| PYSEC-2026-3656 | pypdf denial of service | Medium |
| CVE-2026-84309 | pypdf RCE-class | Critical |
| CVE-2026-84310 | pypdf memory corruption | Critical |
| CVE-2026-84311 | pypdf XFA exposure | High |

pypdf 6.16.1 contains the fix.

## Decision
Bump pypdf 6.14.2 → 6.16.1 via `uv lock --upgrade-package pypdf`. No pyproject.toml edit required — constraint `>=6.14.2,<7.0` (line 117) already admits 6.16.1.

## Risk Analysis (per S53 swarm agent)

### Production usage (5 файлов)

| Файл | API | Criticality |
|---|---|---|
| `src/backend/utilities/pdf_reader.py` | `PdfReader(path)` + `page.extract_text()` | HIGH |
| `src/backend/dsl/engine/processors/rpa/pdf_extract.py` | `PdfReader(BytesIO(data))` + `page.extract_text()` | MEDIUM (skip-if-missing) |
| `src/backend/dsl/engine/processors/rpa/documents.py` | `PdfWriter()`, `add_page`, `write` | MEDIUM (only PdfWriter usage) |
| `src/backend/services/ai/document_parsers/_legacy.py` | `PdfReader(BytesIO(content))` + `extract_text` | HIGH (fallback для PDF-upload'ов) |
| `src/backend/services/ai/rag/multimodal/pdf_ingester.py` | `PdfReader` + `reader.metadata.title/author` + `len(reader.pages)` | HIGH (RAG ingest) |

**Real critical risk**: НЕТ для production кода — всё через stable public API.
**Test-fixture risk**: MEDIUM для `pypdf.generic.*` в `_make_minimal_pdf` (test_pdf_ingester.py:21).

### 4-layer defense-in-depth

1. Cascade fallback: `pdfium → pypdf → PdfReaderUnavailable` (graceful degradation)
2. Lazy import в RPA-processors (`ImportError → exchange.fail`)
3. `markitdown_settings.engine_enabled` toggle (legacy fallback opt-in)
4. Skip-if-not-installed в `PdfExtractProcessor`

### Attack Surface (REAL)

CVE RCE-class per upstream. **Real exploitable** если attacker может передать crafted PDF в upload.
- `/api/v1/rag/*` — capability-gated (но RAG ingest все равно происходит)
- `/api/v1/admin/*` — admin-only
- `/import/bulk-objects` — capability-gated
- `/api/v1/rpa/*` — capability-gated (capability `rpa.pdf.read`)

Attack surface REAL but gated.

## Migration Strategy

1. `uv lock --upgrade-package pypdf` (single-package, within `<7.0` constraint)
2. Verification — tier-ordered test subset (~50 min total):
   ```bash
   # Tier 1 — HIGHEST risk
   pytest tests/unit/utilities/test_pdf_reader.py -v
   pytest tests/unit/services/ai/rag/multimodal/test_pdf_ingester.py -v
   
   # Tier 2 — MEDIUM risk
   pytest tests/unit/dsl/engine/processors/rpa/operations/test_document_processors.py -v
   pytest tests/unit/dsl/engine/processors/rpa/test_pdf_extract.py -v
   
   # Tier 3 — Smoke
   pytest tests/unit/services/ai/document_parsers -v  # if unit-tests exist
   
   # Tier 4 — Full regression
   make test
   ```
3. Если fixture упал → fixture-fix (`pypdf.generic.*` rename detection), ~15 min conditional
4. `uv run pip-audit -r pyproject.toml` → expect 0 pypdf CVE
5. Atomic commit `chore(deps): uv lock --upgrade-package pypdf`

## Pass Criteria

- [ ] `test_pdf_ingester_extracts_text_via_pypdf` — metadata.engine in ('pypdfium2','pypdf') + page_count >= 1
- [ ] `test_pdf_ingester_handles_broken_pdf` — empty chunks + warning
- [ ] `test_pdf_ingester_falls_back_to_pypdf` — cascade не сломан
- [ ] `_make_minimal_pdf` fixture — pypdf.generic.* rename detection (or pass)

## Consequences

- ✅ 5 CVE cleared (2× PYSEC + 3× CVE-2026-8xxxx)
- ✅ Patch-level compliance (ADR-0289)
- ⚠️ Test-fixture risk — MEDIUM conditional fix
- ⚠️ Per-package upgrade isolated blast radius

## Alternatives Considered

- **Defer to S54+**: REJECTED (CVE RCE-class, attack surface REAL).
- **Replace pypdf entirely (e.g., pypdfium2 + custom)**: REJECTED (текущий cascade fallback уже использует pypdfium2 при доступности; 5 production files используют pypdf stable API).
- **Pin до 6.16.0 (не 6.16.1)**: REJECTED (6.16.0 partial fix; 6.16.1 final).
